# Analysis_Instagram
Instagramのインサイト指標を、Instagram Graph API から Google Apps Script(GAS)で取得して Google スプレッドシートへ自動記録するためのソースコード集です。現在は手入力している集計シートを、API取得と定期実行(時間ベースのトリガー)に置き換えることを目的としています。

## 目的

- 手入力しているインサイト数値の転記作業をなくす
- 定期実行できるものはGASトリガーで自動化し、人が書く欄(内容・意図・振り返りなど)は手入力のまま残す
- 数値の取りこぼしを防ぐ(特にストーリーズは投稿から24時間で取得できなくなるため、毎日の自動取得が必須)

## 実行環境

| 項目 | 内容 |
|---|---|
| 実行基盤 | Google Apps Script(スプレッドシートにバインド、または単体スクリプト) |
| データ取得元 | Instagram Graph API(Instagram Login / Facebook Login のどちらかは要確認) |
| 出力先 | Google スプレッドシート(既存の「Instagramシート」の各タブ) |
| 定期実行 | GAS の時間主導型トリガー |
| ソース管理 | Git(GAS との同期は [clasp](https://github.com/google/clasp) を想定) |

## 対象シートと自動化の方針

既存シートの各タブを、API取得で埋められるかどうかで整理しています。「想定」は列見出しの一部しか確認できていない段階の推定で、実装時に確定します。

| タブ | 内容 | 自動化 | 想定する取得方法・頻度 |
|---|---|---|---|
| アカウントインサイト月間 | 月次のリーチ・閲覧・インタラクション・フォロワー増減など | ◎ | `/{ig-user-id}/insights`(`period=day` の日次値を集計) / 月初 |
| アカウントインサイト週間 | 週次の同指標 + 性別・年齢層 | ◎ | 同上 + `follower_demographics` 等 / 週次 |
| フォロワー数/リスト数 | 日次のフォロワー数と変動 | ○ | `followers_count` を毎日スナップショット保存 / 毎日 |
| フィードインサイト | 投稿ごとのリーチ・いいね・保存・コメント等 | ◎ | `/{ig-user-id}/media` → `/{media-id}/insights` / 毎日 |
| ストーリーズインサイト | ストーリーごとの閲覧・離脱・返信等 | ◎ | `/{ig-user-id}/stories` → `/{media-id}/insights` / **毎日(24時間で消えるため)** |
| リールインサイト | リールごとの閲覧・平均視聴時間・保存・シェア・属性 | ◎ | `/{media-id}/insights` / 毎日 |
| dm | DM数・CVR | △ | Graph API では取得に制約があるため、手入力維持の可能性が高い |
| フォロー | フォロー活動の記録 | △ | 手入力維持の可能性が高い |
| ストーリーネタ帳 | 企画メモ | × | 手入力 |
| インサイト改善チェックリスト | 運用チェックリスト | × | 手入力 |

### 自動化しない(手入力のまま残す)列

投稿ごとのタブにある「内容」「意図」「振り返り」「改善」などの運用メモ列は人が書く欄です。スクリプトは数値列のみ更新し、これらの列は上書きしません。

### 計算式の扱い

CVR や割合などの派生指標は、現状シート側の数式で計算しています。スクリプトは**生の数値だけを書き込み**、数式列には触れない方針です(`#N/A` や `#DIV/0!` はデータ未入力のためで、取得後に解消される想定)。

## 認証情報の管理

アクセストークン等はコードに書かず、GAS の **スクリプトプロパティ** に保存します(Git管理外)。

| キー | 内容 |
|---|---|
| `IG_ACCESS_TOKEN` | 長期アクセストークン |
| `IG_USER_ID` | Instagram ビジネスアカウント ID |
| `SPREADSHEET_ID` | 出力先スプレッドシートの ID |

## ディレクトリ構成(予定)

```
Analysis_Instagram/
├── README.md
├── .gitignore
├── appsscript.json      # GAS マニフェスト
├── src/
│   ├── config.gs        # 定数・シート名・列定義
│   ├── api.gs           # Graph API 呼び出し・ページネーション・リトライ
│   ├── token.gs         # トークン更新
│   ├── account.gs       # アカウントインサイト(月間/週間/フォロワー数)
│   ├── media.gs         # フィード・リールのインサイト
│   ├── stories.gs       # ストーリーズのインサイト
│   ├── sheet.gs         # シート書き込み(追記・更新、手入力列の保護)
│   └── triggers.gs      # トリガーの登録・削除
└── docs/                # 列対応表などの設計メモ
```

## セットアップ(予定)

```bash
npm install -g @google/clasp
clasp login
clasp clone <scriptId>    # または clasp create
clasp push
```

その後、GAS エディタでスクリプトプロパティを設定し、`triggers.gs` の登録関数を一度実行します。

## 実装の進め方

1. 各タブの列と API の指標の対応表を作る(`docs/`)
2. API呼び出しの共通部分とトークン更新を実装
3. ストーリーズ(取りこぼしが最も痛い)から自動化
4. フィード・リール、アカウントインサイトの順に追加
5. トリガーを登録して本番運用

## 開発メモ

- ブランチ運用: `main` から作業ブランチを切り、変更後にマージする
- コミット前に `git status` で、トークンやデータが含まれていないことを確認する
- `.gitignore` は `*.json` を除外しているため、`appsscript.json` などコードに必要な JSON は `git add -f` で追加する
