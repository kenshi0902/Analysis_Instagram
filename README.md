# Analysis_Instagram
Instagramのインサイト指標を、Instagram Graph API から Google Apps Script(GAS)で取得して Google スプレッドシートへ自動記録するためのソースコード集です。現在は手入力している集計シートを、API取得と定期実行(時間ベースのトリガー)に置き換えることを目的としています。

## 目的

- 手入力しているインサイト数値の転記作業をなくす
- 定期実行できるものはGASトリガーで自動化し、人が書く欄(内容・意図・振り返りなど)は手入力のまま残す
- 数値の取りこぼしを防ぐ(特にストーリーズは投稿から24時間で取得できなくなるため、毎日の自動取得が必須)

## 実行環境

| 項目 | 内容 |
|---|---|
| 実行基盤 | Google Apps Script(単体スクリプト。出力先シートは `SpreadsheetApp.openById` で指定) |
| データ取得元 | Instagram Graph API(Instagram Login / Facebook Login のどちらかは要確認) |
| 出力先 | Google スプレッドシート(既存の「Instagramシート」の各タブ) |
| 定期実行 | GAS の時間主導型トリガー |
| ソース管理 | Git(GAS との同期は [clasp](https://github.com/google/clasp) を想定) |

## 対象シートと自動化の方針

既存シートの各タブを、API取得で埋められるかどうかで整理しています。「想定」は列見出しの一部しか確認できていない段階の推定で、実装時に確定します。

| タブ | 内容 | 自動化 | 想定する取得方法・頻度 |
|---|---|---|---|
| アカウントインサイト月間 | 月次のリーチ・閲覧・インタラクション・フォロワー増減など | ◎ | `/{ig-user-id}/insights`(`period=day` の日次値を集計) / 月初 |
| アカウントインサイト週間 | 週次の同指標 + 性別・年齢層 | ◎ | 同上 + `follower_demographics` 等 / 週次 |
| フォロワー数/リスト数 | 日次のフォロワー数と変動 | ○ | `followers_count` を毎日スナップショット保存 / 毎日 |
| フィードインサイト | 投稿ごとのリーチ・いいね・保存・コメント等 | ◎ | `/{ig-user-id}/media` → `/{media-id}/insights` / 毎日 |
| ストーリーズインサイト | ストーリーごとの閲覧・離脱・返信等 | ◎ | `/{ig-user-id}/stories` → `/{media-id}/insights` / **毎日(24時間で消えるため)** |
| リールインサイト | リールごとの閲覧・平均視聴時間・保存・シェア・属性 | ◎ | `/{media-id}/insights` / 毎日 |
| dm | DM数・CVR | △ | Graph API では取得に制約があるため、手入力維持の可能性が高い |
| フォロー | フォロー活動の記録 | △ | 手入力維持の可能性が高い |
| ストーリーネタ帳 | 企画メモ | × | 手入力 |
| インサイト改善チェックリスト | 運用チェックリスト | × | 手入力 |

### 自動化しない(手入力のまま残す)列

投稿ごとのタブにある「内容」「意図」「振り返り」「改善」などの運用メモ列は人が書く欄です。スクリプトは数値列のみ更新し、これらの列は上書きしません。

### 計算式の扱い

CVR や割合などの派生指標は、現状シート側の数式で計算しています。スクリプトは**生の数値だけを書き込み**、数式列には触れない方針です(`#N/A` や `#DIV/0!` はデータ未入力のためで、取得後に解消される想定)。

## セットアップ

```bash
clasp push                # src/ を GAS に反映(scriptId は .clasp.json、Git管理外)
```

1. GAS エディタの「プロジェクトの設定」→「スクリプト プロパティ」に以下を登録する。
   | キー | 内容 |
   |---|---|
   | `IG_ACCESS_TOKEN` | 長期アクセストークン |
   | `IG_USER_ID` | Instagram ビジネスアカウント ID |
   | `SPREADSHEET_ID` | 書き込み先スプレッドシートの ID |
   | `IG_API_HOST` | (任意)既定 `graph.facebook.com`。Instagram ログインなら `graph.instagram.com` |
   | `IG_API_VERSION` | (任意)既定 `v23.0` |
2. `checkConfig` → `testConnection` → `initSheets` の順に手動実行して動作を確認する。
3. `runAll` で初回取得を試し、問題なければ `installTriggers` を一度実行する。

### 定期実行の内容

| 関数 | 頻度 | 内容 |
|---|---|---|
| `syncStories` | 6時間おき | ストーリーの最新インサイトで更新(24時間で消えるため) |
| `syncFollowers` | 毎日 1時台 | フォロワー数・フォロー数・投稿数を記録、前日比を計算 |
| `syncMedia` | 6時間おき | 直近30日の投稿を更新し、投稿後1/7/28日時点のスナップショットを記録 |
| `syncAccountAll` | 毎日 2時台 | アカウント日次 → 期間ユニーク値(直近7/30日・週・月) → フォロワー数の推定値補完 の順に実行 |
| `syncAudience` | 毎週月曜 2時台 | オーディエンス属性の最新値で更新 |
| `refreshToken` | 毎週月曜 3時台 | トークン更新(Instagram ログインのみ。それ以外はスキップ) |

### シート書き込みの仕様

- 列はヘッダー名で特定するため、列の並べ替えや手入力列の追加をしても壊れない
- スクリプトが管理する列(`config.gs` の `TABLES`)以外には書き込まない
- キー列(ストーリーID / 日付)で突き合わせ、あれば更新・無ければ追記
- 取得できなかった指標は空で上書きせず、既存の値を残す

## ダッシュボード

GAS ウェブアプリとして、シートのデータを概要・投稿・ストーリーズ・オーディエンスの4タブで表示します。指標の定義と設計の背景は [docs/dashboard-redesign.md](docs/dashboard-redesign.md) を参照。

1. `clasp push` 後、`runBackfill` を一度実行して過去分を取得する(投稿は全件、アカウント日次は30日分、期間ユニーク値は26週・6か月分)。
2. GAS エディタの「デプロイ」→「新しいデプロイ」→「ウェブアプリ」でデプロイし、URL を開く(実行ユーザー: 自分 / アクセス: 自分のみ)。コード更新後は「デプロイを管理」から新しいバージョンを作る。
3. `installTriggers` で定期実行を登録する。

### 比較のルール

- 投稿・ストーリーは実数ではなく「÷リーチ」の率で比べる。代表値は中央値で、サンプル数 n を併記する(n<5 は薄く表示)。
- KPI には前期間(同じ長さの直前の期間)との差を付ける。率は pt 差、実数は変化率。
- リーチ・エンゲージしたアカウントはユニーク数のため日次値を足さない。直近7日・30日は期間指定で取得した値、90日・全期間は週ユニークの平均を使う。
- 投稿は「投稿後1日・7日・28日」時点の値でも比べられる(`API_投稿推移`。機能追加後の投稿から溜まる)。

API 取得分は手入力の既存タブと混ざらないよう、`API_` 接頭辞の専用タブに書き込みます。
