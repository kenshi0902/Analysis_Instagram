# ダッシュボード再構築の提案

現行ダッシュボード(概要・投稿・ストーリーズ・オーディエンスの4タブ)について、**「正しい比較ができているか」**という観点で評価し、再構築案をまとめる。タブ構成は見やすいため維持し、各タブの中身(指標の定義・比較の軸・グラフの選び方)を作り直す。

---

## 1. 結論

現行版は「取得した数値をそのまま並べる」段階で、次の3点で比較の前提が崩れている。

1. **母数が揃っていない** — 投稿ごとのリーチ・いいねを実数で比べているが、フォロワー数・投稿からの経過日数・形式(フィード/リール)が違う投稿を同じ土俵に置いている。
2. **合算してはいけない値を合算している** — 期間のリーチ・エンゲージしたアカウント数を日次値の合計で出している。これらはユニーク数なので、日をまたいで足すと重複して過大になる。
3. **比較対象がない** — KPIが期間の値だけで、前期間・自分の平常値(中央値)・外部ベンチマークのどれとも比べていないため、良いのか悪いのか判断できない。

再構築では、**「率で比べる」「同じ条件で比べる」「必ず比較対象を添える」**の3原則で全タブを揃える。

## 2. 他の分析事例・ベンチマークとの比較

| 観点 | 一般的な分析事例・公式の示唆 | 現行版 | 差分 |
|---|---|---|---|
| エンゲージメント率 | 「インタラクション÷リーチ」(リーチ基準)と「÷フォロワー」(フォロワー基準)の2系統がある。ベンダーによって計算式も母数も違うため、**1つの式に固定して自社の推移で比べる**のが定石 | 率を出していない | 率の定義を決めて全タブで統一する必要がある |
| 重視すべき指標 | Instagram責任者 Adam Mosseri は、主要シグナルとして **視聴時間・いいね/リーチ・送信(シェア)/リーチ** を挙げている。特に送信/リーチは、非フォロワーへの拡散と相関が強いとされる | 平均視聴時間は表示している。いいね・シェアは実数のみ | 「◯◯/リーチ」の率を投稿評価の軸にする |
| ストーリーズ | **完走率 = その日の最後のストーリーのリーチ ÷ 最初のリーチ**、**離脱率 = 終了数 ÷ 閲覧数** が標準。離脱率は何枚目かで大きく変わる(1枚目が高く、後ろほど下がる) | 独自定義の「離脱率 =(終了+次のアカウントへ)÷ 全タップ」。日ごとのシーケンスとして見ていない | 定義を標準に合わせ、「日ごとの連続投稿」単位で見る |
| フォロワー獲得 | 「リーチ → プロフィール訪問 → フォロー」の**ファネル**で、どの段階で落ちているかを見る | フォロー増減の棒グラフのみ | 転換率のファネルを追加する |
| 期間比較 | 前週比・前月比、前年同期比が基本 | フォロワー増減のみ | 全KPIに前期間比を付ける |
| 外れ値 | 1本のバズで平均が大きく動くため、**中央値**と分布で見る | 平均のみ | 中央値と分布(散布図)に変える |

**ベンチマークの扱い**: 外部の平均値は調査元によって大きく異なる。例として、フォロワー基準のエンゲージメント率は 0.30%(Rival IQ、中央値)〜 0.45%(Socialinsider)、リーチ基準は 5.46%(Buffer、中央値)。ストーリーズの離脱率も、約5%(Dash Social)と約24%(Socialinsider、1枚目)のように開きがある。このため、**外部値は参考線にとどめ、主な比較対象は自社の過去中央値**とする。

## 3. 現行版の問題点(タブ別)

### 概要
| 問題 | 何が起きるか |
|---|---|
| リーチ・閲覧数のKPIを日次値の合計で出している | リーチはユニーク数のため、30日分を足すと同じ人を何度も数える。実際の30日リーチより大きく出る |
| 前期間比がない(フォロワー数以外) | 今月が良いのか悪いのか判断できない |
| いいね・コメント・保存を1つの軸で表示 | いいねが桁違いに多いため、コメント・保存の動きが見えない |
| 日次表示のみ | 日々の上下が激しく、傾向が読めない。元シートにあった「週間・月間」の粒度がない |
| フォロワー数が推定値を含む | 推定区間を点線で示してはいるが、KPIの増減にも推定が混ざっている |

### 投稿(フィード・リール)
| 問題 | 何が起きるか |
|---|---|
| リーチ・いいねを実数で比較 | フォロワー数が多い時期の投稿ほど有利になる |
| 投稿からの経過日数を揃えていない | 2日前の投稿と60日前の投稿を同じ累計値で比べてしまう。新しい投稿が不当に低く見える |
| 平均値のみ | リール246本のうち数本のバズで平均が大きく動く |
| フィードとリールで指標が非対称 | リールはフォロー・プロフィール訪問を取得していないため、フォロワー獲得への貢献を比べられない |
| 曜日・時間帯の分析がない | 「いつ投稿すべきか」の判断材料がない |

### ストーリーズ
| 問題 | 何が起きるか |
|---|---|
| 離脱率が独自定義 | 他の事例と比較できない |
| 1枚ずつ独立に表示 | 「その日の1枚目→最後」の連続的な離脱(完走率)が見えない |
| 何枚目かを考慮していない | 1枚目は構造的に離脱率が高いため、位置の違うストーリーを比べると誤解する |

### オーディエンス
| 問題 | 何が起きるか |
|---|---|
| 人数(実数)で表示 | フォロワー・リーチ層・エンゲージ層は母数が違うため、構成比で比べられない |
| 3つの対象を別々のグラフで表示 | 「フォロワーに対して、エンゲージしているのはどの層か」が読み取れない |
| 最新スナップショットのみ | 属性構成の変化を追えない |

### 全体
- 各指標のサンプル数(n)が出ていない。フィード16本のように少ない場合、率や平均の信頼度が判断できない。
- データの鮮度(最終取得日時)や、取得できなかった指標(空欄)の表示がない。

## 4. 比較のルール(全タブ共通)

| ルール | 内容 |
|---|---|
| 率で比べる | 投稿・ストーリーの評価は実数ではなく「÷リーチ」の率を主にする。実数は補助として表示する |
| 同じ条件で比べる | 投稿は「投稿後◯日時点」の値で比べる。形式(フィード/リール)は分けて比べ、形式をまたぐときは率のみ使う |
| 合算しない値は合算しない | リーチ・エンゲージしたアカウントは、期間を指定して API から取得したユニーク数を使う |
| 比較対象を必ず添える | KPIには前期間比と、自社中央値(過去90日)を併記する |
| 代表値は中央値 | 平均は外れ値に引っ張られるため、中央値を基本にする |
| サンプル数を示す | 平均・率には n を併記し、n が少ない(例: 5未満)ときは薄く表示する |
| 推定値を区別する | 推定値を含むときはグラフ・KPIで明示する |

### 指標の定義(案)

| 指標 | 計算式 | 用途 |
|---|---|---|
| エンゲージメント率(ER) | インタラクション合計 ÷ リーチ | 投稿の総合評価(リーチ基準で統一) |
| いいね率 | いいね ÷ リーチ | Mosseri の主要シグナル |
| シェア率(送信率) | シェア ÷ リーチ | 非フォロワーへの拡散力 |
| 保存率 | 保存 ÷ リーチ | 有益性・見返し需要 |
| リーチ率 | 投稿リーチ ÷ 投稿日時点のフォロワー数 | フォロワー外への広がり |
| プロフィール訪問率 | プロフィール訪問 ÷ リーチ | 興味喚起 |
| フォロー転換率 | フォロー ÷ プロフィール訪問 | プロフィールの説得力 |
| フォロワー増加率 | 純増 ÷ 期首フォロワー数 | 規模の違う期間どうしの比較 |
| ストーリー完走率 | その日の最後のリーチ ÷ 最初のリーチ | ストーリー構成の評価 |
| ストーリー離脱率 | 終了 ÷ 閲覧数 | 1枚ごとの評価(何枚目かと併記) |

## 5. タブ別の再構築案

### 概要(アカウント全体の健康状態)
- **粒度切替**: 日 / 週 / 月。週・月は日次値の合算ではなく、期間のユニーク値を使う。
- **KPI(6つ)**: フォロワー数、フォロワー増加率、期間リーチ(ユニーク)、ER、プロフィール訪問率、フォロー転換率。
  - 各KPIに「前期間比(▲▼と%)」と「過去90日中央値との差」を併記する。
- **グラフ**
  1. フォロワー数の推移(現行を維持。推定区間は点線)
  2. フォロワー獲得ファネル: リーチ → プロフィール訪問 → フォロー(期間合計と転換率)
  3. リーチとERの推移(リーチとERは単位が違うため、2つのグラフに分ける)
  4. 反応の内訳: いいね・コメント・保存・シェアの**率**の推移(実数ではなく ÷リーチ で揃える)

### 投稿(フィード・リール)
- **形式切替**: フィード / リール / すべて。「すべて」では率の指標のみ表示する。
- **評価時点の切替**: 投稿後1日 / 7日 / 現在。7日未満の投稿は「集計中」と表示し、中央値の計算から除く。
- **KPI**: 投稿数、ER中央値、シェア率中央値、保存率中央値、リーチ率中央値(リールは平均視聴時間の中央値も)。
- **グラフ**
  1. 散布図: 横軸リーチ × 縦軸ER。中央値の十字線で4象限に分け、「広く届いて反応も良い」投稿を見つける。点にホバーで投稿内容を表示する。
  2. 投稿ごとのER推移(時系列)と中央値線。外れ値を強調する。
  3. 曜日 × 時間帯のヒートマップ(ER中央値、セルに n を表示)。
- **一覧表**: 率の列(ER・シェア率・保存率・リーチ率)を追加し、中央値との差を色付けする。上位・下位25%をラベル表示する。

### ストーリーズ
- **日ごとのシーケンス単位で表示**: 1日の連続投稿を1グループとして、1枚目からのリーチ残存率を折れ線で表示する。
- **KPI**: 投稿日数、1日あたり平均枚数、完走率中央値、1枚目の離脱率、返信率(返信÷リーチ)。
- **グラフ**
  1. 何枚目かごとの離脱率(全期間の中央値)。何枚目から離脱が増えるかを見る。
  2. 日ごとの完走率の推移。
  3. タップ操作の構成比(次へ・戻る・終了・次のアカウントへ)。実数ではなく比率で表示する。
- **一覧表**: 日付・何枚目・閲覧・離脱率・戻る率。「戻る」が多いストーリーは、見返されている(情報量が多い)ことの目安になる。

### オーディエンス
- **構成比(%)に変換**し、フォロワー・リーチ層・エンゲージ層を**同じグラフで並べる**(年齢層ごとに3本の棒)。
- **反応指数** = エンゲージ層の構成比 ÷ フォロワーの構成比。1を超える層が、フォロワーの中でも特に反応している層とわかる。
- 性別は構成比の帯グラフ、都市・国は上位10と「その他」に集約する。
- 週次の推移: 構成比の変化(例: 25-34歳の割合)を折れ線で表示する。

## 6. 必要なデータの追加

ダッシュボードの計算だけでは対応できないものは、取得処理を追加する。

| 追加データ | 理由 | 実装方法 | 規模 |
|---|---|---|---|
| 期間のユニークリーチ・エンゲージしたアカウント | 日次合計は過大になるため | `/insights` を週・月の `since/until` で `total_value` 取得し、`API_アカウント期間` タブへ保存 | 小 |
| 投稿の経過日数別スナップショット | 投稿後1日・7日時点での比較のため | `syncMedia` 実行時に、投稿後 N 日目の値を `API_投稿推移` タブへ追記(キー: メディアID+経過日数) | 中 |
| リールのフォロー・プロフィール訪問 | フィードとの比較のため | `REEL_METRICS` に追加して取得可否を検証(リールで取得できない場合はフィードのみの指標とする) | 小 |
| オーディエンス属性の履歴 | 構成比の推移を見るため | キーに取得週を含め、週次で蓄積 | 小 |
| 投稿のテーマ・企画(任意) | 「どんな内容が効くか」を比べるため | 手入力の既存タブの「内容・意図」とメディアIDで結合、またはタグ列を追加 | 中 |

**データの制約**
- 経過日数別スナップショットは、実装した日以降の投稿からしか溜まらない。過去の投稿は「現在の累計値」で代用する。
- 投稿日時点のフォロワー数は、フォロワー数シートの範囲内(実測+推定の30日程度)しかわからない。範囲外の投稿のリーチ率は、最も近い日の値で近似する(または表示しない)。
- オーディエンス属性はフォロワー100人以上が条件(現状は満たしている)。

## 7. 進め方(案)

| フェーズ | 内容 | 追加取得 |
|---|---|---|
| 1 | 率・中央値・前期間比・n表示の導入。オーディエンスの構成比化と3対象の並列表示。ストーリーズのシーケンス化と離脱率の定義変更 | なし(現データで可能) |
| 2 | 期間ユニークリーチの取得と、概要の日/週/月切替。リールのフォロー・プロフィール訪問 | 小 |
| 3 | 経過日数別スナップショットと、投稿の評価時点切替。曜日×時間帯ヒートマップ | 中 |
| 4 | オーディエンス履歴、投稿テーマとの結合 | 小〜中 |

## 8. 決定事項(2026-11-14 確定)

| 論点 | 決定 | 反映内容 |
|---|---|---|
| ERの定義 | **両方表示** | 主はリーチ基準(KPI・散布図・ヒートマップ)。一覧表にフォロワー基準のERも併記 |
| 最重要KPI | **リーチ拡大** | 概要の先頭KPIは「期間リーチ・リーチ率・シェア率」。投稿一覧の既定の並び順はリーチ率 |
| 投稿テーマの分析 | **今回は見送り** | 後日、手入力タブとの結合を検討 |
| 着手範囲 | **フェーズ1〜3** | オーディエンス属性の履歴(フェーズ4)は対象外 |

### 実装上の補足
- 経過日数別スナップショットは、投稿後 **1日・7日・28日** の3時点で記録する。記録の遅れを抑えるため、`syncMedia` は6時間おきに実行する。
- 期間ユニークリーチは、API の上限(1回あたり30日)のため次のように扱う。
  - 直近7日・30日: そのままユニーク値を取得(前の同じ期間も取得して前期間比に使う)
  - 90日・全期間: 週ごとのユニーク値の平均(「週平均リーチ」)で表示
  - 月次: 31日ある月は末尾30日分で近似し、「近似」と表示する
- 投稿のリーチ率は、投稿日時点のフォロワー数が記録の範囲内にある投稿だけで計算する(範囲外は空欄)。
